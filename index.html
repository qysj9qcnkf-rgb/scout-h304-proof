    Computed in your browser by the real review code (app/lib/call-review/end-notes.ts) from the call's saved record. One drop, at 0:11, back 7 s later. The second "leave" was the End call that ended the call.

    What dropped at 0:11? The page's own record says LiveKit reported client_initiated with no End call and no page close. The call page's LiveKit library hangs up by itself only when the browser starts to leave the page (beforeunload: a tapped link, a reload begun, an app hand-off) or freezes it (freeze). Which of the two was not logged then. From now on it is.

    What is stored

    Per drop: the cause (one of: page closed, page leaving, page frozen, tab hidden, device offline, network lost, call server, unknown), a short trail of browser events with the second of the call they happened (for example hidden@38 beforeunload@41 lk_disconnected@41), and per rejoin how many seconds the shopper was away. Event names and seconds only. It sits with the call's existing end record and goes into the call review's audio notes. Nothing changes for the shopper or in what Mia says.
